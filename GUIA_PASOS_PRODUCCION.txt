1. COMO USAR Y MOSTRAR EL PAQUETE PORTABLE ACTUAL (BETA HOY)
==============================================================================
El archivo HARMONY_BETA_HOY.zip contiene todo lo necesario para correr la app
de forma 100% autonoma.

REQUISITO UNICO:
- Tener instalado Java 17 o superior (verificar en consola con: java -version).

PASOS PARA EJECUTAR:
1. Descomprimir el archivo HARMONY_BETA_HOY.zip en cualquier carpeta.
2. Hacer doble clic sobre "INICIAR.bat".
3. Se abrira una ventana de consola negra. Mantenerla abierta.
4. Abrir el navegador web en: http://127.0.0.1:8080
5. Para cerrar la app: presionar Ctrl+C en la ventana de consola o cerrarla.

DATOS Y CUENTAS INCLUIDAS:
La app ya viene con datos cargados para probar de inmediato:
- Cuenta 1: gladito@example.test / Clave: Harmony123
  (Creador de la banda "Nebula Waves", toca sintetizador)
- Cuenta 2: pepito@example.test / Clave: Harmony123
  (Integrante de la banda, toca bajo, tiene permisos para publicar)

FLUJO SUGERIDO DE PRUEBA:
- Iniciar sesion como Gladito: ver el feed con reproductor de audio integrado.
- Ir a "Mis bandas" -> "Nebula Waves": ver la lista de integrantes e instrumentos.
- Modificar el instrumento o permisos de Pepito.
- Crear una nueva publicacion propia o en nombre de la banda.
- Registrar un usuario nuevo desde la pantalla de login (requiere 8+ caracteres,
  una mayuscula y un numero).
- Desde el nuevo usuario: buscar la banda, solicitar unirse, y luego aprobarlo
  con la cuenta de Gladito asignandole su instrumento.
- Calificar perfiles (1 a 5 estrellas) y reaccionar a publicaciones (likes).

DONDE SE GUARDAN LOS DATOS:
- La app guarda los datos localmente en un archivo dentro de la subcarpeta "data".
- Si queres reiniciar la base de datos a su estado original de fabrica,
  simplemente cerra la app, borra la carpeta "data" y volve a ejecutar INICIAR.bat.

2. COMPARTIR ONLINE HOY MISMO SIN INSTALAR NADA NI PAGAR UN VPS ($0)
==============================================================================
Si tu amigo u otra persona quiere probar la app desde su propia computadora
o desde el celular SIN que ellos tengan que descargar el ZIP ni instalar Java:

OPCION A: Cloudflare Tunnel (100% Gratuito, Seguro y sin abrir puertos)
----------------------------------------------------------------------
1. Descargar el ejecutable liviano "cloudflared" para Windows desde:
   https://github.com/cloudflare/cloudflared/releases (archivo cloudflared-windows-amd64.exe)
2. Renombrarlo a "cloudflared.exe".
3. Con Harmony corriendo en tu PC (tras ejecutar INICIAR.bat), abrir una consola
   PowerShell o CMD en la carpeta donde esta cloudflared.exe y escribir:
   
   .\cloudflared.exe tunnel --url http://127.0.0.1:8080

4. Cloudflare generara una URL publica y segura con HTTPS, por ejemplo:
   https://palabra-aleatoria-123.trycloudflare.com
5. Le pasas ese enlace a tu amigo y puede entrar directamente desde su celular o PC.
   Toda la navegacion pasa por tu maquina de forma encriptada y segura.
6. Cuando cerras la consola de cloudflared, el enlace deja de funcionar.

OPCION B: ngrok (Alternativa clasica)
-------------------------------------
1. Descargar ngrok desde https://ngrok.com
2. Ejecutar: ngrok http 8080
3. Copiar la URL https publica que muestra en pantalla.

3. PASO A BASE DE DATOS REAL (MYSQL 8.4)
==============================================================================
La version portable utiliza la base de datos embebida H2 (en modo archivo) para
no exigir la instalacion de MySQL en la maquina que prueba la beta.
El codigo fuente de Harmony ya incluye el soporte para MySQL y el script
Flyway listo para crear las tablas reales.

COMO ACTIVAR MYSQL:
1. Instalar MySQL 8.0 o posterior (o levantarlo en Docker).
2. Crear una base de datos vacia con codificacion UTF8mb4:
   CREATE DATABASE harmony_beta CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
3. Definir las siguientes 4 variables de entorno antes de ejecutar la app:
   - SPRING_PROFILES_ACTIVE = mysql
   - DB_URL = jdbc:mysql://localhost:3306/harmony_beta?serverTimezone=UTC
   - DB_USER = tu_usuario_mysql
   - DB_PASSWORD = tu_contrasena_mysql

4. Ejecutar el JAR:
   java -jar harmony.jar --spring.profiles.active=mysql

MIGRACIONES FLYWAY INCLUIDAS:
- Al arrancar con el perfil mysql, Flyway detecta la base de datos y ejecuta
  automaticamente el script "V1__beta_schema.sql".
- Este script crea las 16 tablas relacionales con sus claves primarias, foraneas,
  indices de rendimiento y restricciones de unicidad correspondientes.
- No es necesario ejecutar ningun script SQL a mano.

4. DESPLIEGUE EN LA NUBE GRATUITO (PLATAFORMAS PAAS - CERO MANTENIMIENTO)
==============================================================================
Si queres que la app este disponible en Internet 24/7 sin pagar un VPS y sin
tener que administrar Linux ni configurar servidores:

OPCION RECOMENDADA: Render.com o Railway.app
---------------------------------------------
1. Subir el repositorio de Harmony a una cuenta de GitHub (publica o privada).
2. Crear una cuenta en Render (https://render.com).
3. Crear un "PostgreSQL" o "MySQL" gratuito en Render o utilizar Supabase/Aiven
   (brindan instancias de base de datos relacionales gratuitas en la nube).
4. Crear un "Web Service" en Render conectando tu repositorio de GitHub:
   - Build Command: ./gradlew bootJar
   - Start Command: java -jar build/libs/Harmony-0.0.1-SNAPSHOT.jar --spring.profiles.active=mysql
5. En la seccion "Environment Variables", agregar:
   - DB_URL: la URL de conexion provista por la base de datos
   - DB_USER: el usuario de la base
   - DB_PASSWORD: la clave de la base
6. Render compila la app, la despliega y te entrega un dominio HTTPS gratuito
   (por ejemplo: https://harmony-app.onrender.com) con certificado SSL automatico.

5. DESPLIEGUE EN SERVIDOR PROPIO (VPS CON DOCKER + CADDY SSL)
==============================================================================
Si deciden contratar un servidor virtual privado (VPS) como Hetzner Cloud (aprox
4 a 5 dolares al mes), la arquitectura recomendada es Docker Compose con Caddy
para resolver SSL de forma 100% automatica.

ESTRUCTURA DE ARCHIVOS:

1. Archivo "Dockerfile" en la raiz:
-----------------------------------
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY build/libs/Harmony-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

2. Archivo "docker-compose.yml":
--------------------------------
services:
  app:
    build: .
    restart: unless-stopped
    environment:
      - SPRING_PROFILES_ACTIVE=mysql
      - DB_URL=jdbc:mysql://db:3306/harmony_beta?serverTimezone=UTC
      - DB_USER=harmony
      - DB_PASSWORD=${DB_PASSWORD}
    depends_on:
      - db

  db:
    image: mysql:8.4
    restart: unless-stopped
    environment:
      - MYSQL_DATABASE=harmony_beta
      - MYSQL_USER=harmony
      - MYSQL_PASSWORD=${DB_PASSWORD}
      - MYSQL_ROOT_PASSWORD=${DB_ROOT_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql

  caddy:
    image: caddy:alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
    depends_on:
      - app

volumes:
  mysql_data:
  caddy_data:

3. Archivo "Caddyfile" (para certificados SSL automaticos):
-----------------------------------------------------------
tu-dominio.com {
    reverse_proxy app:8080
}

COMANDO DE DESPLIEGUE EN EL VPS:
$ docker compose up -d --build
(Caddy se encarga de hablar con Let's Encrypt, obtener el certificado HTTPS y renovarlo).

6. SEGURIDAD REQUERIDA PARA PRODUCCION
==============================================================================
Antes de abrir la app al publico general en produccion, se deben aplicar dos
ajustes de seguridad esenciales en el codigo:

1. PROTECCION DE COOKIES DE SESION Y HTTPS:
   - Configurar en application-prod.properties:
     server.servlet.session.cookie.secure=true
     server.servlet.session.cookie.http-only=true
     server.servlet.session.cookie.same-site=strict
   - Esto evita que la sesion sea robada por conexiones inseguras o ataques XSS.

2. PROTECCION CONTRA FUERZA BRUTA EN /login:
   - Implementar un interceptor o filtro con Caffeine Cache o Bucket4j.
   - Regla recomendada: Si una misma direccion IP o una misma cuenta falla 5 veces
     seguidas la contrasena, bloquear intentos por 15 minutos.

7. SERVICIO DE CORREO Y RECUPERACION DE CONTRASENA ($0)
==============================================================================
Actualmente los usuarios no tienen opcion para resetear contrasena si la olvidan.

PROVEEDOR RECOMENDADO ($0 DE COSTO):
- Resend (https://resend.com): Plan gratuito de 3.000 emails al mes (100 por dia).
  Excelente entregabilidad y configuracion en 5 minutos.
- Brevo (https://brevo.com): 300 correos al dia gratuitos via SMTP.

PASOS DE IMPLEMENTACION:
1. Crear tabla en MySQL:
   CREATE TABLE password_reset_tokens (
       id BIGINT AUTO_INCREMENT PRIMARY KEY,
       token VARCHAR(100) NOT NULL UNIQUE,
       user_id BIGINT NOT NULL,
       expiry_date DATETIME NOT NULL,
       CONSTRAINT fk_reset_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
   );
2. Agregar endpoint GET/POST "/forgot-password" para solicitar el link.
3. Generar token criptografico temporal (validez 20 minutos) y enviar email con enlace.
4. Agregar endpoint GET/POST "/reset-password?token=..." con validacion de la nueva clave.

8. PANEL DE MODERACION Y ADMINISTRACION
==============================================================================
Permite gestionar la comunidad sin tener que entrar a la base de datos:

1. ROL DE ADMINISTRADOR:
   - Agregar el valor 'ADMIN' a la columna de roles del usuario.
   - Proteger la ruta en SecurityConfig: requestMatchers("/admin/**").hasRole("ADMIN").

2. FUNCIONALIDADES DEL PANEL (/admin):
   - Buscador de usuarios por username o email.
   - Boton "Suspender cuenta" / "Reactivar cuenta": Al cambiar "user.enabled = false",
     el filtro ActiveAccountFilter que ya esta implementado en la app expulsara
     inmediatamente la sesion del usuario bloqueado.
   - Listado de posts y comentarios recientes con opcion de "Dar de baja" (marcado
     logico deleted = true).

9. POLITICA DE COPIAS DE SEGURIDAD (BACKUPS RPO 4H) Y MONITOREO 24/7
==============================================================================
1. POLITICA DE RESPALDO (RPO 4 HORAS):
   - RPO (Recovery Point Objective): En caso de falla catastrofica, la perdida
     maxima tolerable de datos es de 4 horas.
   - Script cron en el servidor (ejecutado cada 4 horas: 00:00, 04:00, 08:00, etc.):
     mysqldump -u harmony -p${DB_PASSWORD} harmony_beta | gzip > /backups/harmony_$(date +\%Y\%m\%d_\%H\%M).sql.gz
   - Retencion: Guardar backups de los ultimos 7 dias y purgar los mas viejos.

2. MONITOREO Y ALERTAS ($0):
   - Activar el endpoint de salud de Spring Boot Actuator (/actuator/health).
   - Crear cuenta gratuita en UptimeRobot (https://uptimerobot.com).
   - Configurar un monitor HTTP hacia https://tu-dominio.com/actuator/health cada 5 minutos.
   - En caso de caida o lentitud, UptimeRobot te envia un alerta al instante
     por Email, Telegram o Discord.
   - RTO (Recovery Time Objective): Permite actuar rapidamente para restablecer el servicio
     en menos de 6 horas.
